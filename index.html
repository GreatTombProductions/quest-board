Withdrawn Sources

Retractions, corrections, and expressions of concern are public — but they are filed where the citing text isn't, so content publishers, supplement vendors, and citation aggregators keep borrowing withdrawn authority. The reader at the decision boundary (patient, student, journalist, clinician checking a claim) cannot route a withdrawal notice to the claims citing it without identifier-level tooling. This is the portage layer: Retraction Watch CSV + Crossref metadata → paste-a-text check + full-database search.

Check flow: paste text with citations; DOIs and PMIDs are extracted client-side (shared case table with a Python pipeline twin) and matched against the snapshot — every notice for an identifier renders with nature (retraction / expression of concern / correction / reinstatement), date, journal, publisher, authors, reason chips, and DOI/PubMed links; unmatched identifiers get a typed 'no notice found' plus an optional live Crossref member-metadata check. Search flow: the whole snapshot by title, first author, or journal. Method page: pinned receipt (URL, SHA-256, fetched-at, records), field semantics, extraction + matching rules, coverage caveats, attribution.

Retraction Watch Database (Retraction Watch / Center for Scientific Integrity), made publicly available by Crossref at gitlab.com/crossref/retraction-watch-data — dated snapshot pinned by SHA-256 in the receipt · 72,646 records; 173,785 normalized identifiers (111,324 DOIs + 62,461 PMIDs); snapshot fetched 2026-09-25, covers notices through 2026-09-19

Served-Model Check

AI resellers, aggregators, wrappers, and vendor compatibility routes can serve a different model than the one a customer is paying for — silently, with no error and no per-response signal, and the model itself cannot be trusted to self-report identity (documented: 4/12 endpoints confidently assert wrong identity facts; some are trial-unstable, inventing a different wrong identity on every identical probe). Customers at purchase/renewal decision boundaries (developers, small businesses on metered AI APIs, procurement teams) currently have no way to test 'the model I configured is the model that ran' from their own evidence. AI-API customers benefit from transparency: the probe is computable from their own API access, requires no vendor cooperation, and produces a dated record that is useful exactly when a substitution dispute does.

Paste-box verifier for the question no billing dashboard answers: is the served model the declared model? Two channels are scored against the declared id: (1) the self-report channel — a calibrated identity probe, scored by first-person assertion only (a name inside a rejection sentence never counts; the rule that flipped four apparent adoptions to failures in calibration); (2) the endpoint channel — the response's own model / modelVersion field. Verdicts are fail-closed: contradiction signal (different model, version mismatch, unstable self-report across reps, explicit denial, conflicting developer attribution), no contradiction observed (explicitly not proof of identity), or insufficient signal (never a clean bill of health from absence). Watch mode scores dated probe logs into a drift timeline — a signature change mid-contract is the finding a single check cannot see. Probe runner script ships with the site (probe.py, OpenAI-compatible / Anthropic / Google styles). All scoring runs in the browser; nothing you paste leaves the page.

Client-side probes of the user's own endpoint captures + the public OpenRouter model list (catalog for the declared-model picker and context cross-check) · 447 catalog model ids; 20-case calibration corpus (12 model endpoints x 3 reps + pin controls), reproducing documented failure classes: trial-unstable confabulation, stable-stale self-reports, product-level naming, honest refusals; 1 documented vendor routing case (DeepSeek legacy ids)

The Unverifiable Model — billed ID, served generation, and the alias that isn't what it says

API aggregators and model vendors profit from identity opacity: retired model IDs stay listed and keep billing while silently routing to a different generation (measured live 2026-09-24: a retired alias drifted its price twice in five days while serving its successor), generation swaps are presented as continuity, and the models themselves confidently self-report wrong identities (4 of 12 tested). The customer's mental model is 'I pay for model X'; the vendor's meter is 'an ID that resolves to whatever we route it to.' The decision boundary: continue on an alias, migrate, or dispute a bill — all unanswerable from the customer side, because the vendor's dashboard is the only declared-identity surface and it is the thing under question.

A static, obligation-free Model ID verifier for small operators (AI-API resellers, builders with model-specific behavior contracts, solo developers on metered APIs): enter a billed model ID, and the tool pulls the API-declared metadata (context, pricing, reasoning flags, created date), runs a small behavioral fingerprint battery (six calls, permission-pair slice), and diffs both against the generation-era expectation. Output: a one-page report — 'billed for X, API declares Y, behavior matches Z' — with drift flags for retired aliases and silent reroutes. The in-tomb instrument (behavioral_fingerprint.py, the selfid-probe battery, live-model-metadata discipline) is the verified prototype; the public version is the same shape with a web form instead of an API key.
